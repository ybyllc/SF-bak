# 菜单系统模块化拆分计划

## 1. 拆分方案

根据用户要求，将菜单系统拆分为以下三个主要文件：

### 1.1 子菜单管理文件

* **menu.c** - 子菜单管理

  * 包含所有子菜单的定义

  * 子菜单逻辑实现

  * 新增子菜单的维护

### 1.2 显示管理文件

* **menu\_core.c** - 显示管理

  * 主菜单显示

  * 各子菜单显示

  * OLED 操作封装

### 1.3 输入处理文件

* **menu\_input.c** - 输入处理

  * 编码器输入处理

  * 按键事件处理

  * 遥控器输入处理

  * 接口暴露给子菜单

## 2. 实现步骤

### 2.1 创建新文件结构

1. 创建 `menu_core.h` 和 `menu_core.c`
2. 创建 `menu_input.h` 和 `menu_input.c`

### 2.2 拆分功能

1. **子菜单管理文件 (menu.c)**：

   * 保留子菜单相关的函数和数据

   * 定义子菜单结构和管理函数

   * 实现子菜单逻辑

   * 提供添加新子菜单的接口

2. **显示管理文件 (menu\_core.c)**：

   * 移动所有显示相关的函数

   * 实现主菜单和各子菜单的显示逻辑

   * 提供显示接口函数

3. **输入处理文件 (menu\_input.c)**：

   * 移动所有输入处理相关的函数

   * 实现编码器和按键输入的处理逻辑

   * 提供输入处理接口函数

   * 接口暴露给子菜单

### 2.3 重构代码

1. **修改 menu.c**：

   * 保留子菜单逻辑

   * 调用 menu\_core 和 menu\_input 的函数

2. **修改 menu\_core.c**：

   * 实现所有显示逻辑

   * 提供显示接口

3. **修改 menu\_input.c**：

   * 实现所有输入处理逻辑

   * 提供输入处理接口

   * 接口暴露给子菜单

4. **更新包含关系**：

   * 确保各模块之间的包含关系正确

   * 避免循环包含

### 2.4 测试和验证

1. 确保拆分后的菜单系统功能正常
2. 测试所有子菜单的显示和交互
3. 验证新子菜单的添加流程
4. 测试输入处理的正确性

## 3. 接口设计

### 3.1 子菜单管理接口 (menu.h)

```c
// 输入处理相关接口
void MenuInput_Init(void);
void MenuInput_HandleEncoder(int32_t count);
void MenuInput_HandleKeyEvent(uint8_t event);
```

### 3.2 显示管理接口 (menu\_core.h)

```c
// 显示相关接口
void MenuCore_Init(void);
void MenuCore_DisplayMainMenu(void);
void MenuCore_DisplayPage(MenuPageType page);
```

### 3.3 输入处理接口 (menu\_input.h)

```c
// 输入处理相关接口
void MenuInput_Init(void);
void MenuInput_HandleEncoder(int32_t count);
void MenuInput_HandleKeyEvent(uint8_t event);
```

## 4. 优势

1. **模块化**：各模块职责明确，易于维护
2. **可扩展性**：添加新子菜单只需修改 menu.c
3. **可维护性**：代码结构清晰，便于理解和修改
4. **灵活性**：各模块可以独立修改和测试
5. **可读性**：代码组织更加合理，易于阅读

## 5. 预期效果

* 用户可以在 menu.c 中轻松添加新的子菜单

* 显示
